## Problem Statement · 问题

本地项目部署完成后，面板已经能发现它，但 CF 控制仍依赖项目自带的启动脚本。用户在网页选中一个正常运行的新项目，仍会看到 CF 按钮置灰；有脚本的项目也可能遇到权限、关闭目标、常驻进程占用任务队列、历史网址被误当成在线网址等问题。

用户需要的是“需要时开，不需要时关”，而非给每个项目部署公网入口。CF 的开关还应与本地项目启停分开：关闭 CF 后，本地应用照常使用。

## Solution · 方案

保留 Docker / Project 的项目发现与现有分类。在这两个分类的网页上提供统一的按需 CF 操作：

1. 新发现的项目默认关闭，发现与浏览本身不创建隧道配置或进程。
2. 点击“开启 CF”后，识别并核验这个项目的入口；一个有效入口直接使用，多个有效入口由用户选择，缺少有效入口就显示具体原因。
3. 面板托管对应隧道。任务完成真实核验后显示当前公网网址，用户可以打开或复制。
4. 点击“关闭 CF”只撤下该隧道；保存入口选择，供下次重新核验后复用。
5. 使用 Quick Tunnel 临时网址。重新建立隧道会更换网址；固定域名和新增开机自启不属于本期。

**能力界限：** Cloudflare 官方明确列出 Quick Tunnel 的 SSE 限制、200 个进行中请求上限及无可用性保证。本期验收网页和普通 HTTP(S) 可达性，Agent2API 的聊天流式 SSE 不列为已支持能力。界面在开启说明中简短标明这项限制。

## Implementation Decisions · 实现决定

### 1. 分工与唯一业务入口

- Docker / Project 模块提供项目归属和运行线索；CF 接入能力不再以专属脚本存在为唯一前提。
- 新增一个统一的 CF 管理模块，对调用方提供入口准备、动作计划、运行状态三个操作面；Docker 与 Project 共用同一套启停、核验和失败处理规则。
- 该模块内部接合实际运行信息、用户级进程管理和面板状态存储。公开调用方只提交项目及已选候选入口，不拼接启动命令、猜服务名或自行读取日志网址。
- 任务中心继续负责短时动作的串行执行及日志。长期运行的隧道由独立进程管理负责。
- 分类页负责操作与状态；详情页保留只读展示定位。本期沿用现有导航、卡片选择、任务中心和通知入口。

### 2. 入口准备与归属核验

- 入口准备由点击开启、重建或打开入口选择触发。全量项目扫描只收集轻量线索，关闭项目没有持续公网探测。
- Docker 以当前容器运行信息和已确认的 Compose 归属为依据，区分宿主端口发布、容器网络入口和 host 网络。
- 已发布端口核对实际绑定地址、协议、宿主端口、容器端口和所属容器；通配绑定转换为本机可达地址后再核验。
- 仅有端口声明时，只把它作为容器内候选。读取当前容器网络地址后，从面板实际运行环境验证可达性；宿主网络路线不通时给出原因，业务容器端口映射、网络模式与运行配置保持原样。
- Project 优先复用已确认的项目服务、进程归属及现有入口配置；启动参数和端口号只作线索，实际监听及项目归属共同成立后才接入。纯源码目录不会因此自动启动。
- IPv4、IPv6、HTTP 与正确证书的 HTTPS 均按真实地址处理；容器同一服务的等价入口去重。一个项目本期至多选择一个入口、运行一条面板托管隧道。
- 一个有效候选可自动使用；多个有效候选首次让用户选择。保存的是项目内服务与端口等语义选择，容器 IP、PID 等实例信息只作当次核验，重新开启时重新解析。
- 已保存的选择仍指向同一服务且核验通过时自动复用；选择已消失、出现歧义或归属变化时重新展示候选，保留“待选择”状态。
- 候选入口使用服务端生成的标识及版本凭证。客户端选择其他项目的候选、提交过期凭证或伪造地址均得到明确错误；命令参数独立传递，项目名和地址不拼成 shell 表达式；业务动作开始前再次核对项目归属和当前候选。
- 接入范围限已归属于该本地项目的 HTTP(S) 服务；排除任意外部 URL、URL 用户凭据、非 HTTP 协议以及未归属的本机监听。外部跳转不会成为新的源站候选。
- 入口的网页子路径用于打开和核验；CF 实际连接的是整个 HTTP 服务，界面说明这不是仅开放单个页面。

### 3. 网页行为与请求契约

- 主按钮文案为“开启 CF”“关闭 CF”；保留“重建 CF”作为次级动作。旧动作标识 `cf_create`、`cf_refresh`、`cf_disable` 及其批量请求地址保持兼容。
- 新增读取 CF 状态和准备候选入口的读取接口，分别使用 `GET /api/assets/{object_id}/cf` 与 `GET /api/assets/{object_id}/cf/targets`。二者均要求现有面板登录，且只观察、核验，不创建隧道或保存开关意愿。
- 状态响应包含接入能力、资源归属、用户开关、实际状态、当前网址、最后核验时间、最近任务和分阶段错误；候选响应包含候选标识、版本凭证、名称、协议、来源、可达性及失败原因。
- 沿用批量动作提交契约，增加可选的逐项目 `cf_target_map`，每项只含候选标识和版本凭证；旧客户端省略该字段时，仅对唯一或已保存且有效的候选自动继续。
- 批量选择中缺少入口、需要选择或发生错误的项目，进入原有 `skipped` 结果；其他项目照常入队。保留 `action`、`queued_count`、`tasks`、`skipped` 字段与 202 返回语义。
- `cf_create` 表示保证该项目隧道开启；已有在线隧道时复用。`cf_refresh` 表示用户明确要求重建，可重新完成入口准备并获得新网址。`cf_disable` 表示保证该面板隧道关闭，重复关闭保持幂等。
- 入口选择弹窗在确认前只准备候选；取消后既有配置和隧道保持原样。多个项目的待选入口按项目分别展示，避免把同一选择应用到所有项目。
- 从网页提交后显示任务链接和“已入队”，按任务与状态结果更新卡片；最终结果到达前保持进度态。
- 关闭动作以是否存在可确认归属的隧道或待处理开启请求为依据，不依赖源站仍在线，也不依赖 cloudflared 二进制仍可用于新建。
- 网址复制按钮只使用当前核验通过的网址；历史网址独立显示为失效记录。入口弹窗和状态变化保留键盘焦点、取消键、可读反馈与移动端可用布局。

### 4. 状态与持久化

- 复用面板状态数据库，新增独立的 CF 记录；项目首次请求实际 CF 动作前，空记录按默认关闭解释，扫描不会给所有项目批量建配置。
- 记录至少包含稳定项目归属键、来源类别、已选入口描述、用户开关、操作代次、实际状态、运行标识、宿主启动标识、当前及历史网址、核验时间、关联任务与结构化错误。
- 归属键复用已有项目/Compose 上下文；同名目录不同路径分别识别，同一项目的重复发现入口共享 CF 记录。此规则仅服务于 CF，不重新设计全项目身份系统。
- 面板 CF 数据与临时运行资料归面板所有；业务源码目录和原有脚本保持原样。资料沿用面板私有目录与文件权限规范，日志有大小或轮转上限。
- 旧 CF 能力字段保留兼容读取，补充独立的状态字段；历史 `enabled` 之类能力标记不承担“当前在线”的含义。
- “接入能力”“用户开关”“实际状态”分别存取。源站断开或启动失败时，用户曾请求开启与当前异常可以同时呈现；用户可重试或关闭。

| 实际状态 | 界面含义 | 当前网址 |
| --- | --- | --- |
| 已关闭 | 没有当前面板托管隧道 | 空 |
| 开启中 | 已受理，正在准备、启动或核验 | 空 |
| 在线 | 当前进程与源站归属成立，公网核验通过且仍在有效期内 | 当前已核验网址 |
| 关闭中 | 已受理关闭，清理尚在执行 | 空 |
| 异常 | 开启、访问、运行或清理失败；附具体阶段 | 空，旧网址单独标注 |

“待选择”“未满足接入条件”“外部管理”是接入条件或资源归属提示，与上表状态分开。状态读取以 CF 的当前观察覆盖项目发现缓存，旧快照不会重新带回旧网址。

### 5. 长期进程与重启语义

- 本期运行目标为当前 WSL / Linux，使用面板运行用户的 systemd 临时服务托管 cloudflared，资源名由面板命名空间和项目归属键确定。
- 临时服务与面板服务属于独立生命周期。面板的短重启不主动终止已核验的隧道；面板启动后重新核对它的运行标识、项目归属和网址。
- 不新增宿主开机启用项，不开启或调整用户 linger，也不修改全局 systemd、sudo、Docker 或 Cloudflare 配置。宿主重启后 CF 关闭，只保留上次入口选择。
- 核验以当前服务 InvocationID、进程信息及操作代次为依据，单个旧 PID、目录名或模糊进程匹配均不足以控制资源。
- cloudflared 使用独立运行上下文，用户原有命名隧道配置保持原样；复用已安装的可执行文件，缺少依赖时报告具体缺项，安装与升级仍归系统基础设施模块。
- 用户级进程管理缺失、访问失败或资源冲突时在对应阶段结束任务。关闭清理失败保留异常及待清理事实，禁止虚报已关闭。
- cloudflared 自身的传输重连可继续工作；进程终止或宿主重启后，本期由用户重试开启，不新建常驻的自动启动策略。

### 6. 任务、并发与失败收尾

- 开启/重建任务只执行“准备入口 → 启动独立运行资源 → 取得网址 → 公网核验 → 保存结果”，不会等待长期 cloudflared 进程退出。
- 每个项目串行处理实际变更，系统任务中心原有全局串行规则继续生效；重复开启请求在任务执行时复用已存在的同目标隧道。
- 状态更新带操作代次，已结束或已被后续操作替代的启动结果不得覆盖新状态。按入队顺序执行“开启后关闭”时，最终为关闭，迟到的域名输出不会重新显示在线。
- 关闭按任务队列执行，可在开启任务尚未结束时提交并展示“等待关闭”；不承诺抢占其他任务。启动有硬超时，因此关闭请求不会被长期 cloudflared 运行无限阻塞。
- 原子发布当前 CF 结果；入队失败、状态写入失败、任务进程异常退出都需要有可核对的任务/运行记录，避免留下已成功的假象。任务与面板状态数据库分别存在，采用幂等操作及补偿核对，不假定跨库写入天然原子。
- 单次入口准备总限 15 秒、单个 HTTP 核验上限 5 秒；开启/重建实际执行总限 120 秒，其中公网建立与核验至多 90 秒，结束后最多 15 秒清理本代资源。排队等待单独显示。
- 关闭实际执行总限 15 秒。达到上限时返回关闭失败和待清理信息，后续重试只处理同一已确认资源。
- 未核验运行资源设有独立于 HTTP 请求和任务子进程的启动截止机制，核验通过后才进入常驻态。超时、失败、进程异常退出后清理本代产生的未核验资源。面板重启发现上轮未核验的悬挂资源时先处理其收尾，避免变成无主隧道。
- 错误按入口归属、入口可达性、依赖、进程托管、CF 建连、公网核验、关闭清理、状态持久化分阶段记录。错误只包含必要诊断，排除环境凭据和业务响应正文。

### 7. 在线核验与失效处理

- 本地核验使用项目已有页面/健康路径，其次是站点根路径；只使用轻量读取请求。模型调用、账号测试、注册、登录提交等业务操作不属于 CF 健康检查。
- HTTP 协议有效且可归属的入口可以作为候选；正常页面或健康响应构成成功核验。401/403 等应用登录限制单独展示，只有本地与公网响应特征确认来自同一应用时才视作“可达，需要登录”。404、业务 5xx、CF 错误页及 CF 挑战页均不当作核验成功。
- 获取日志中的网址只是中间步骤。在线需要同时满足：当前托管进程存在、源站仍属于目标项目、当前临时域名属于本代进程、相同核验路径的公网响应与本地应用特征一致。
- 只接受有效 HTTPS 的当前 Quick Tunnel 域名；核验保持 TLS 校验，限制跳转次数，并区分源站、DNS、CF 连接和公网 HTTP 各层错误。
- 面板运行期间，仅对已有面板 CF 记录且尚未关闭的项目进行状态维护，覆盖开启中、在线、关闭中与异常待清理。在线项目每 30 秒至多启动一次公网核验，观察结果有效期 60 秒；过期显示“待核验/异常”，不会永久沿用上次在线结果。
- cloudflared 已退出、源站归属失配时立即撤下当前网址；源站确定停止、项目消失或端口已归其他对象时，只清理已确认归属的面板隧道，保留入口选择和原因。源站自行恢复后由用户重试 CF。
- 关闭以已确认的托管进程停止为主要判据；旧域名 DNS 仍存在或返回 CF 离线页面不表示关闭失败。正式验收还核对旧网址不再返回目标业务内容。
- 通知模块继续沿用原发送规则，只消费同一份真实 CF 网址结果；关闭、异常或过期时 CF 当前网址为空，不新增自动通知或自动模型请求。

### 8. 旧隧道兼容

- 明确关联、归属可核验的旧 systemd 隧道保留外部管理标记及既有显式控制路径；操作前核对服务及目标，错误仍返回任务中心。
- 只有旧脚本或历史域名文件、缺少可核验管理对象时，作为外部线索展示，并说明尚缺哪项关联。原始前台脚本不会直接进入串行任务执行器。
- 旧服务处于 masked 等明确停用状态时保持该状态；本轮排除自动解除、重建覆盖、批量迁移或从项目名猜测 unit。
- 同一已确认来源已有外部隧道时，面板不会默认另开重复隧道，也不会把关闭面板隧道解释成关闭所有同名 CF 进程。

## Testing Decisions · 测试决定

### 测试入口与原则

主要测试接缝沿用现有 **已登录的面板 HTTP 请求 → 真实动作计划 → 真实任务队列/执行器 → 状态读取与页面结果**。通过这一个用户可观察入口覆盖 CF 管理模块、Docker/Project 入口适配、任务中心和展示整合。

- 测试断言状态、实际管理的模拟资源、任务结果、当前网址及业务对象保持不变，而非私有方法调用次数或恰好生成了某段命令文本。
- 真实 CF 管理逻辑参与测试，只替换 Docker/systemd 观察、进程管理、网络响应和时钟等外部依赖。把整个 CF 模块替换成“总是成功”的 mock 不构成回归证据。
- 生成的独立任务入口至少执行一次真实临时子进程链路，外部命令由隔离替身承接，覆盖参数、模块加载、依赖路径、输出与退出码传递。
- 并发和迟到结果使用可控事件与时钟制造，避免依赖长时间 sleep；进程管理替身允许模拟启动成功、注册延迟、挂起、异常退出和关闭失败。
- 所有 Python 回归通过项目的 `scripts/test_isolated.sh` 执行；使用临时 HOME、数据库、日志、项目目录和本地 HTTP fixture。自动化回归不调用真实业务 Docker/systemd，不访问 CF 或模型接口。

### 必测行为

| 编号 | 观察场景 | 必须得到的结果 |
| --- | --- | --- |
| T01 | 首次发现、列表刷新、只读状态查询、取消入口弹窗 | 默认关闭，零新隧道配置/进程，业务文件与容器保持原样 |
| T02 | 新 Docker / Project 没有 CF 脚本 | 有真实入口时进入新托管路径；纯源码/非 HTTP 给出原因 |
| T03 | 真实发布端口、仅容器网络入口、host 网络、IPv4/IPv6 | 使用归属正确且实测可达的地址；EXPOSE 不冒充宿主映射 |
| T04 | 多服务、多网络等价入口、多个候选、候选全部失效 | 等价入口去重，歧义要求选择，零有效入口保持未开启 |
| T05 | 重开时 IP/PID 改变、同名目录、项目替换、端口复用 | 重解析语义选择；失配/旧凭证无业务副作用，其他项目不受影响 |
| T06 | 真实请求入队并执行开启 | 入队状态与在线分开；核验后当前网址可读，随后普通任务可执行 |
| T07 | 重复开启、两页面并发、开启后立即关闭、迟到输出 | 每项目至多一个托管资源，最终服从队列顺序，旧结果不复活 |
| T08 | 关闭、重复关闭、源站已停、二进制丢失后关闭 | 已确认资源可独立清理，本地项目始终保持原运行结果 |
| T09 | cloudflared 缺失、用户管理器缺失、注册/DNS/HTTP 失败 | 阶段错误明确，任务有界结束，残留清理可核对，当前网址为空 |
| T10 | 开启/核验/关闭超时、持久化/入队失败、执行器退出 | 无假成功，无永久占用队列，待清理资源可重试且归属准确 |
| T11 | 面板重启、宿主启动标识改变、外部杀掉托管进程 | 核对后保留真实连接或撤下旧网址；宿主重启保持关闭 |
| T12 | 在线探测过期、源站归属变化、历史域名文件仍在 | 正确显示核验时间及异常；旧快照/通知不会重新带回旧网址 |
| T13 | 应用登录页、401/403、404、业务 5xx、CF 错误页 | 区分应用可达与错误；状态不因任意 HTTP 响应就变为在线 |
| T14 | 批量包含成功、待选、失效入口、非适用分类 | 每项目单独入队或跳过，原响应字段兼容，其他项目继续执行 |
| T15 | 未登录、跨项目候选、伪造 URL、外部跳转、HTTPS 证书错误 | 现有登录和目标约束生效；没有建立或误关隧道 |
| T16 | 明确旧 unit、仅脚本/文件、masked unit、同名无关进程 | 归属清楚才控制；原有停用状态及无关项目保持原样 |
| T17 | 桌面/移动端/键盘入口选择、任务轮询、复制/打开网址 | 真实 DOM 交互可用，当前状态统一，取消与禁用原因清楚 |

### 既有测试先例与执行门禁

复用现有批量动作、项目/容器扫描、能力矩阵、任务工作线程及分类页路由测试的组织方式；前端复用现有 Node DOM 测试和隔离浏览器验收方式。现有测试中“没有脚本就没有 CF 能力”的旧断言需要以新场景替换，保留其真正保护的非适用分类及项目隔离要求。

新增行为先失败后实现。每轮记录精确红/绿证据，再执行完整隔离 Python、前端测试、Ruff、JavaScript 语法和差异检查。代码审查沿用 Standards / Spec 两路独立只读审查，处理有效发现后再完成交付门禁。

### 正式 Web 验收与完成条件

1. 加载经过测试和审查的实现后，从正式面板选中 Agent2API，点击开启；如出现候选选择，通过页面完成。
2. 任务中心实际结束为成功，CF 状态在线；打开页面给出的公网网址，读取项目页面或健康响应，确认来自 Agent2API。
3. 通过同一 Web 界面关闭，观察关闭任务成功与当前网址撤下；旧网址不再返回业务内容，Agent2API 的本地健康仍正常。
4. 再次通过 Web 开启，确认复用了有效的入口选择、重新核验并拿到当前网址；返回最后实际有效的公网网址。
5. 保存网页操作、任务结果、访问核验和本地健康证据。手工命令启动隧道、直接修改 DOM 按钮状态、仅发动作请求拿到 202，均不算此链路通过。
6. 实测范围为项目网页/轻量 HTTP；测试结果分别写明功能测试、正式加载和正式 Web 验收状态，任何一项未完成都单独列出。

## Out of Scope · 范围之外

- 自动给所有发现的项目开公网、预生成每项目脚本、自动启动本地业务项目。
- 固定域名、Cloudflare 账号接入、命名隧道管理、Access/邮箱认证配置、新增 CF 开机自启。
- Quick Tunnel 的 SSE 流式兼容承诺、无限并发、生产可用性保证，以及其他 TCP/UDP 穿透产品。
- 自动安装/升级 cloudflared，新增 root 提权规则，修改宿主全局配置或业务容器端口/网络。
- Windows 原生、macOS、SSH 远端的 CF 运行管理，以及给 Node/Python/Agent 等其他分类增加 CF 动作。
- 旧隧道批量迁移、解除 masked、接管归属不清的服务、整套项目身份或任务中心重构。
- 自动发送通知、自动模型调用，及与本功能无关的 Router、业务服务重启或配置修改。
