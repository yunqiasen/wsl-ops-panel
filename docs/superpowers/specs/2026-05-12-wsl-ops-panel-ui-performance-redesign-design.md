# WSL Ops Panel 界面重构与性能优化设计

## 1. 目标

把现有 WSL Ops Panel 重构成一个更干净、更现代的浅色运维面板，同时把“按钮卡、页面卡、首屏慢”的问题压下去。

本次只聚焦两件事：

- **视觉重构**：把现有界面改成轻量浅色 SaaS 风格，统一层级、间距、字体、卡片和按钮样式
- **性能优化**：减少首屏同步工作，去掉外链依赖，把终端和版本查询改成按需加载

本次不改：

- 后端业务模型
- 权限模型
- 凭证与配置文件
- 终端的 PTY 交互逻辑本身

---

## 2. 现状问题

### 2.1 视觉问题

当前界面存在这些明显问题：

- 页面块太重，阴影和边框语言不统一
- 信息层级弱，页面看起来像拼起来的
- 导航、卡片、详情页、日志页、终端页之间风格割裂
- 登录页太平，缺少统一的品牌感

### 2.2 性能问题

当前慢点主要来自：

- `base.html` 还引用外链 htmx，增加不必要依赖
- `app/static/app.js` 作为全站脚本，终端相关逻辑会在非终端页也初始化
- `asset_detail` 页会同步拉版本信息，首屏容易卡
- 多层 DOM + 重阴影 + 高频重绘让按钮反馈显得拖

---

## 3. 设计方向

采用 **轻量浅色极简 SaaS** 风格。

### 3.1 视觉原则

- 浅灰白背景为主
- 少阴影，多边框，多留白
- 蓝青色作为唯一主强调色
- 卡片做扁平分层，不做花哨装饰
- 保留专业感，不做“工具箱拼贴感”

### 3.2 字体原则

- 正文字体选清爽、稳定的无衬线字体
- 代码/终端区使用等宽字体
- 不使用夸张字体，不追求花哨

### 3.3 终端风格

- 终端页继续保持真实 PTY
- 终端页视觉统一到整站，但保持它自己的工作台感
- 不回退成假 `<pre>` 或 textarea 日志框

---

## 4. 范围

### 4.1 必做

- 重做 `base.html` 全局壳
- 重做 `overview.html`
- 重做 `category.html`
- 重做 `asset_detail.html`
- 重做 `tasks.html`
- 重做 `logs.html`
- 重做 `settings.html`
- 重做 `terminals.html`
- 重写 `app/static/app.css`
- 优化 `app/static/app.js`
- 去掉 `base.html` 中的外链 htmx
- 让终端相关资源只在终端页加载
- 让资产详情页版本信息改成按需获取或轻缓存

### 4.2 不做

- 不改 Docker / Node / Python / systemd 的业务逻辑
- 不动账号、密码、配置文件
- 不新增管理功能
- 不改服务部署方式

---

## 5. 页面设计

### 5.1 全局壳 `base.html`

统一三层结构：

- 左侧导航
- 顶部页头
- 中央内容区

优化点：

- 统一页面标题和副标题规则
- 统一导航 active 样式
- 去掉外链脚本依赖
- 给每页留页面级挂载点，避免全站一把梭初始化

### 5.2 总览页

总览页只保留三类信息：

- 分类入口
- 核心指标
- 最近任务 / 最近异常

不要堆过多说明文字。

### 5.3 分类页

分类页改成更紧凑的资产卡片网格：

- 每张卡只展示最关键的 3~5 个信息点
- 版本、状态、路径、标签分层显示
- Docker、systemd、Node、Python、host、system 统一卡片语言

### 5.4 详情页

详情页改成“左信息、右操作”的结构。

重点：

- 版本列表不要在首屏同步阻塞
- 操作按钮要有立即反馈
- 详情信息和操作区分层更清楚

### 5.5 任务 / 日志 / 设置

这三页统一成轻量面板：

- 减少大段文本块
- 日志采用更清晰的卡片和折叠区
- 任务状态更直观

### 5.6 登录页

登录页跟全站统一风格：

- 更干净
- 更稳定
- 不做花哨背景

---

## 6. 性能设计

### 6.1 资源加载

- `htmx` 改成本地资源或直接移除外链依赖
- `app/static/app.js` 改为按页面激活
- 终端页才加载 xterm 相关资源
- 其他页面不初始化终端逻辑

### 6.2 数据加载

- `asset_detail` 的版本信息改为按需获取
- 分类页只拿摘要数据，不在首屏做重查询
- 版本列表能缓存就缓存，不能缓存就延迟取

### 6.3 交互响应

- 点击按钮后先出局部反馈
- 任务执行继续后台化
- 减少同步阻塞和 DOM 大面积重绘

### 6.4 样式性能

- 减少重阴影和大面积渐变层叠
- 控制层级数量
- 统一间距和边框系统，避免重复样式

## 8. 验收标准

### 8.1 视觉验收

- 页面看起来统一
- 信息层级清楚
- 不再有“东一块西一块”的拼装感
- 登录页、总览页、分类页、详情页风格一致

### 8.2 性能验收

- 非终端页不再初始化终端库
- 版本查询不再明显拖慢详情页首屏
- 按钮点击后响应更快
- 页面切换不再有明显卡顿感

### 8.3 功能验收

- 原有功能保持可用
- 终端仍是真 PTY
- 任务日志仍能正常看
- 资产动作仍能正常发起

---

## 9. 实施顺序

建议按这个顺序做：

1. 先重做全局壳和样式系统
2. 再改各页面模板
3. 然后拆分前端脚本和懒加载逻辑
4. 最后处理详情页版本查询性能
5. 跑测试并做本地验收

---

## 10. 结论

这次重构的核心不是“再加功能”，而是把现有面板变得：

- 更好看
- 更轻
- 更顺手
- 更像一个真正的运维后台
